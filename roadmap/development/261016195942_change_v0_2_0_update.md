## 1. 変更内容と理由

スペックシート v3 の「改訂について」による。

1. **色（トークン）**：ライト・ダークとも WCAG 2.2 AA を満たすよう見直し。状態色を図形用と文字用（`-text`）に分け、`--color-border-input` を追加。`--blink-dim-opacity` を 0.55 → 0.75。v2 の「コントラスト未達を許容」は取り消し
2. **多言語化**：日本語・英語・中国語（簡体字）に対応。文言はすべて辞書から引き、書体は `<html lang>` で言語ごとに切り替える
3. **ドキュメントの多言語化**：README を3言語（`README.md`・`README.en.md`・`README.zh-Hans.md`）で用意する。ほかの文書は日本語のまま
4. **環境設定（新規画面 S05〜S05c）**：一般（言語・表示テーマ・終了の確認）・音・アプリ情報・プライバシーポリシー
5. **設定の保存**：環境設定の5項目（言語・表示テーマ・音量・振動・終了の確認）だけを `localStorage` に保存する
6. **画面の微修正**
   - S03f：「今後この確認を表示しない」を追加。最初のフォーカスは「終了する」（v2 の差分をモックに取り込み済み。実装は v0.1.0 で対応済み）
   - 音の設定を S01 から S05a へ移す
   - S01 のヘッダーは歯車だけにする。テーマのメニュー（S01e）と GitHub リンク（fix `261012000812_fix_favicon_and_github_link.md` で追加したもの）はなくす

## 2. プランアセットの整合の確認結果

- **ファイル**：スペックシートに挙げた4つのデザインアセットがそろい、版番号はすべて `_v3`。マスターSVGは v2 とバイト単位で同一
- **画面ID**：スペックシートの一覧とモックの画面が19件で一致（S00〜S05c・S90）。S01e・S02・S04 は欠番として明記されている。機能要件から参照されない画面はない
- **トークン**：モックの `:root` の値は `tokens_v3.css` とすべて一致。「決めたいこと」の節は残っていない（「決まったこと」だけ）
- **コントラスト**：トークンから計算して確認した（ライト／ダーク）
  - 文字（4.5:1）：本文・補足文・状態ラベル（`-text` と `-soft`・地・面）・主ボタン・危険ボタン、いずれも通過。最小はライトの `--color-state-ok-text` / `--color-state-ok-soft` で 4.60
  - 図形・境界（3:1）：状態色とリングの地、入力欄の枠と面・地、フォーカスリング、いずれも通過。最小はライトの `--color-border-input` / `--color-bg` で 3.07
  - 超過の明滅の暗い側（0.75 で地に重ねた色と地）：ライト 3.33、ダーク 3.85
  - disabled の文字は WCAG の対象外（ライト 2.20、ダーク 2.56）
- **辞書**：モックの辞書は `ja`・`en`・`zh-Hans` とも124キーで、過不足なし。プレースホルダも一致（英語は `settings.bells.count`・`settings.bells.strikes`・`settings.start_bar.summary` が複数形の形ごとに書かれている）。モックの要素が参照するキーは124キーすべてで、未使用キーはない
  - うち `sample.title_short`・`sample.title_long` の2キーは、モックの見本の表示名（利用者の入力の例）で、UIの文言ではない。`src/` の辞書には移さない（122キー）

## 3. 確認した点と決定（261016 にユーザーと合意。承認後に SPEC_v3 へ反映する）

1. **PWA の表示名の言語**（スペック §2「PWA の表示名も、言語に合わせる」）
   - 問題：マニフェストは静的な1ファイルで、アプリ内で選んだ言語を読めない。Chrome・Edge 148 からは `name_localized` などで言語ごとの名前を書けるが、選ばれるのはブラウザの言語設定に合う名前で、アプリ内の言語の選択には追従しない（[Localization support for web app manifests](https://developer.chrome.com/blog/manifest-localization)）
   - **決定：PWA の表示名は英語表記「LT Timekeeper」で固定する**（`name_localized` は使わない）。マニフェストの `lang` は `en`、`description` も英語にする。ページの題名（`<title>`）は、アプリ内で選んだ言語に合わせる
   - `short_name` は委任事項（文言）として「LT Timer」とする（v0.1.0 は「LTタイマー」）
   - SPEC_v3 §2「言語の決まり方」の「PWA の表示名も、言語に合わせる」を、この決定に書き換える
2. **プライバシーポリシーの版の表記**（S05c「このポリシーはバージョン {version} 時点のものです」）
   - **決定：アプリのバージョン（`package.json` の `version`）を入れる**。ポリシーの文面を変えていなくても、リリースごとに数字が変わることを受け入れる
3. **OSS のライセンス全文**（S05b）
   - 問題：MIT License などは、配布物に著作権表示と許諾文を含めることを求める。S05b に名前とライセンス名を並べるだけでは足りない可能性がある
   - **決定：一覧と同じ仕組みで、ライセンスの全文をまとめたテキストファイル（`third_party_licenses.txt`）をビルド出力に含める**。画面からのリンクは足さない（画面構成を変えないため）
   - SPEC_v3 §2「アプリ情報」と §5「OSS一覧（ビルド時）」に、全文ファイルの同梱を書き足す

## 4. 進め方の方針（委任事項として決めたこと）

- **起動直後のちらつき**：静的に書き出した HTML は1言語でしか描けない。`app.html` の先頭で小さなインラインスクリプトを動かし、保存値とブラウザの言語から `lang` と `data-theme` を描画前に決める。S00 の「読み込み中…」は3言語を持たせて `lang` で出し分ける（外部への通信は増えない）
- **i18n の自動検査**：キーの型（`ja` から生成）、ロケール間のキーとプレースホルダの一致、未使用キー、`.svelte` 内の文字列の直書きを1コマンド（`bun run check:i18n`）で検査し、CI でも実行する
- **疑似ロケール**：開発ビルドだけで有効にする（公開版の言語選択には出さない）。切り替えの方法は imple で決める
- **e2e**：既存の e2e は日本語の文言に依存しているため、Playwright のロケールを `ja-JP` に固定し、言語ごとのテストを別に足す
- **OSS 一覧**：依存を増やさず、Vite のプラグインを自作して、クライアントのバンドルに入ったモジュールが属するパッケージの名前・ライセンス（と全文）を集める。具体的な形は imple で決める
- **README**：現行の README にある開発・ビルド・リリースの情報は `CONTRIBUTING.md`（新設）へ移し、README は利用者向けに書き直す。スクリーンショットは `docs/images/` に版番号なしの固定名で、言語ごとに撮る
