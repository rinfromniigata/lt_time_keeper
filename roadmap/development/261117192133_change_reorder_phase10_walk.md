## 1. 変更内容と理由

### 1.1 いまの問題

- **番号順と記載順のずれ**：Phase 10 の walk が W10-16 → W10-17 → W10-18 → W10-1 → … → W10-15 の順に並んでいる。W10-16〜W10-18 は新しく足した項目で、移動した項目ではないため、番号順と記載順がずれる理由がない。tasks では同じずれを `261117170640` で直したが、walk は「checkコマンドが通る（先頭）」の並びを保つために残していた
- 共通規則の「実行順と依存の整合」は、記載順を ID の番号順とする。「checkコマンドの項目を先頭に置く」と両立させるには、未着手の W10-1〜W10-15 の ID をすべて振り直す必要があり、旧 ID の行が15行残るため、採らない

### 1.2 直し方

- W10-16・W10-17・W10-18 を、ID を変えずに W10-15 の直後へ、この順で移す。Phase 10 の walk は W10-1 → … → W10-15 → W10-16 → W10-17 → W10-18 の番号順になる
  - 番号順と記載順が一致するので、旧位置に移動先を残す1行は不要
- 依存はすべて前方のまま
  - W10-16 は T10-9・T10-13・T10-14・T10-16（tasks。Phase 10 の walk の前にすべて済む）
  - W10-17・W10-18 は W10-16（移したあとも前にある）
  - W10-1〜W10-15 のうち、W10-16〜W10-18 に依存するものはない
- 「checkコマンドが通る → モックとの照合 → 判断を要する検証」の並びからは外れる。T10-16 の時点で checkコマンドの全7段が通っていることを確かめてあり（tasks の引き継ぎ）、W10-1〜W10-15 を先に行っても、自動検査の失敗を後続の検証に持ち込むおそれは小さい。W10-1〜W10-15 の修正で checkコマンドが壊れていないことは、末尾の W10-16 で最後にまとめて確かめられる
