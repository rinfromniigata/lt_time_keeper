# 修正記録: PWA の e2e（W5-2）が CI で不安定だった

## 症状
- `v0.1.0` タグの Actions（run 38148361822）で `bun run test` が失敗し、build・zip・ドラフトリリースに進まなかった（W6-4 不合格）。
- 失敗したテストは `e2e/pwa.e2e.ts` の「W5-2: 版の違うビルドでは、再読み込みのあとに古いキャッシュだけが消える」。55 件は通過。
- エラー: `page.evaluate: Execution context was destroyed, most likely because of a navigation`（`cacheNames()` 内）。

## 原因
- 「再読み込み」を押したあと、`持ち時間 5:00` の表示で読み込み直しの完了を待っていた。この文言は押す前の画面にも出ているため（持ち時間がもともと 5:00）、読み込み直しの途中で `caches.keys()` を呼んでしまい、遷移と競合した。
- 同種の S01f のテストは、直前に 10:00 へ変えてから 5:00 に戻るのを待つので、本物の読み込み直しを待てており、影響を受けない。
- ローカルでは通り、実行が遅い CI でだけ顕在化した。アプリ本体の不具合ではない。

## 修正（テストのみ）
- `e2e/pwa.e2e.ts`: 「再読み込み」のクリックを `page.waitForEvent('load')` と同時に待ち、続けて `#splash` が消えるのを待ってから、キャッシュ名を調べる。
- 要件・設計・インターフェース・タスク構成・確定事項への影響なし（軽微な修正）。アプリのコードとバージョン（0.1.0）は変更なし。

## 検証
- `e2e/pwa.e2e.ts` を `--workers=1 --repeat-each=15` で 165 件通過。
- `bun run test:e2e` を 2 回実行し、どちらも 56 件通過。
- CI 相当の遅い環境での再現はできていない。最終確認は、タグを打ち直したあとの Actions で行う。
- 参考: `--repeat-each` を複数ワーカーで走らせると、このファイルのテストが共有の `service-worker.js` を書き換え合って失敗する（テストの設計上の制約。CI は 1 ファイル内を直列で実行するため該当しない）。
