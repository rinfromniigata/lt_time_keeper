# lt_time_keeper スペックシート

LT（ライトニングトーク）やプレゼンテーションの時間を計る、個人用のタイムキーパーWebアプリ。

---

## 1. 目的と想定用途

- 登壇者の持ち時間を計り、残り時間と状態（通常・予鈴・超過）を、会場の後ろからでも一目でわかるように示す
- 決めた時点でベルを鳴らし、時間を知らせる。日本の学会やLTで使われる「1鈴・2鈴・3鈴」の習慣に合わせる
- 想定する使い方は次の2つ
  - ノートPCをプロジェクターにつなぎ、全画面で映す
  - スマートフォンを登壇者の手元や演台に置く
- 使うのは開発者本人だけ。1台で完結し、端末間の連携やサーバーは持たない

## 2. 機能要件

### 設定

- 持ち時間を分・秒で入力できる。プリセット（3・5・10・15・20分）と分・秒の増減ボタンを使える（S01）
- 持ち時間が0のあいだは開始できず、理由が表示される（S01a）
- ベルを追加・編集・削除できる。ベルごとに、基準（残り／超過後）、時刻、鳴らす回数（1〜3回）を決められる（S01、S01d）
- ベルは時刻の早い順に自動で並ぶ。件数に上限はない（S01c）
- ベルの番号は並び順で振る。3件以下なら「1鈴」のように表記し、4件以上なら「1」のように数字だけにする。計測画面の「次のベル」は、3件以下なら「1鈴まで」、4件以上なら「4番目のベルまで」と表記する（S01、S01c、S03）
- ベルの行の補足文は自動で決まる。「ここで黄（予鈴）に」「ここで赤（超過）に」「持ち時間より長いため鳴りません」のどれにも当たらないベルは「—」とする。メモ欄は設けない。モックの「質疑の終了などに」「デモ開始の目安」は例示として扱う（S01、S01a、S01c）
- 「残り」が持ち時間より長いベルだけを「鳴らないベル」とする。持ち時間と等しいベルは、開始と同時に鳴る
- 同じ時点に複数のベルがあるときは、回数の多い方を1回だけ鳴らす
- 持ち時間とベルの時刻は、どちらも最大 99:59 とする
- 「ベルを追加」で開いたシートには、「削除」の代わりに「キャンセル」を出す（S01d）
- 音量の初期値は70%、振動の初期値はオンとする（S01）
- 持ち時間より前に来る「残り」基準のベルには、鳴らないことが警告として表示される。開始は止めない（S01a）
- ベルが0件でも開始できる（S01b）
- 表示名を任意で入力できる。長い表示名は計測画面で1行に省略される（S01、S01c、S03a）
- 音量を調整でき、ベルの音を試しに鳴らせる（S01）
- ベルと同時に振動させるかを選べる。スイッチは振動に対応した端末でだけ表示する（S01）
- テーマを「OSに合わせる・ライト・ダーク」から選べる（S01e）
- ページを開いた直後は、次の初期値が入っている（S01）
  - 持ち時間：5:00
  - 1鈴：残り1:00で1回
  - 2鈴：残り0:00で2回
  - 3鈴：超過+1:00で3回
- 設定は保存しない。ページを開き直すと初期値に戻る

### 計測

- 「開始」を押すと、すぐに計測が始まる（S01 → S03）
- 計測中は次の情報を表示する（S03）
  - 残り時間の数字
  - 進み具合を示すリング
  - 経過時間と持ち時間（通常のときだけ。予鈴・超過・一時停止のときは、同じ位置に状態ラベルを出す）
  - 表示名
  - 次のベルまでの時間（残りのベルがなければ出さない）
- 状態は3段階で、色・リング・状態ラベルで示す。色だけに頼らない
  - 通常（緑）：計測開始から
  - 予鈴（黄）：最初のベルが鳴った時点から（S03a）。最初のベルが残り0:00以降にある場合、予鈴の段階はない
  - 超過（赤）：残り0:00の時点から（S03b）
- 0:00を過ぎても止まらず、超過時間を「+」付きで数え上げる。超過中は数字とリングがゆっくり明滅する。OSの「視差効果を減らす」設定が有効なときは明滅しない（S03b）
- 各ベルの時点で、指定した回数だけ音を鳴らす。振動がオンなら同時に振動させる
- ベルは画面が見えている間だけ鳴らす。タブが裏にあった間に過ぎたベルは、戻ってきてもあとから鳴らさない。表示と状態は、戻った時点の正しい値にする
- 一時停止と再開ができる。一時停止中は表示が灰色になり、主ボタンが「再開」に替わる（S03c）
- 計測中は、トークン `--controls-hide-delay` の時間だけ操作がないと、操作ボタンとキー操作の案内が隠れる（S03e）
  - デスクトップではマウスカーソルも隠す
  - マウス移動・キー入力・タップで再び表示する
  - 一時停止中は隠さない
- 「終了」ボタンまたは Esc キーで、終了の確認を出す（S03f）
  - 確認中も計測は止めない
  - 最初のフォーカスは「続ける」に置く
  - 「終了する」を選ぶと S01 に戻る
- S01 に戻ったとき、直前に使った持ち時間・ベル・表示名がそのまま残る。値はメモリ上に持つだけで保存はしない
- デスクトップでは次のキー操作が使える（S03、S03f）
  - Space：一時停止・再開
  - F：全画面
  - Esc：終了の確認
  - 確認中の Enter：終了する
  - 確認中の Esc：続ける
- 全画面表示に切り替えられる。ボタンは、Fullscreen API に対応していて、かつ広い画面（720px以上）のときだけ表示する（S03）
- 計測中は画面のスリープを防ぐ。スリープを防げないときや音を出せないときは、計測画面の上部に警告を出す。警告は閉じられる（S03d）

### アプリ全体

- PWAとしてインストールでき、2回目以降は通信なしで起動・計測できる
- 初回の読み込み中は起動画面を出す（S00）
- 新しいバージョンを受け取ったら、設定画面の上部で知らせ、再読み込みを促す（S01f）
  - 計測中に受け取った場合は、S01 に戻ってから知らせる
  - 閉じた場合は、次に開いたときに新しいバージョンになる

## 3. 非機能要件

- **時間の正確さ**
  - 残り時間は、開始時刻と一時停止の合計時間から毎回計算する。カウンターを積み上げる方式にはしない
  - そのため、タブの切り替えや画面の再描画の遅れで表示がずれない
  - ベルは、表示の秒が切り替わるのと体感でずれずに鳴る
- **オフライン**：アプリ本体と画面に必要な資源は、すべてService Workerで事前にキャッシュする
- **通信**：外部への通信をしない。解析ツール、外部フォント、外部の音源は使わない
- **個人情報**：収集・保存しない
- **アクセシビリティ**
  - 状態は色に加えて、リングの残量・ラベル・明滅で伝える
  - キーボードだけで操作でき、フォーカスが見える
  - 「視差効果を減らす」設定を尊重する
  - コントラストの扱い：ライトテーマでは、状態色を文字に使う箇所（状態ラベルの通常 3.52:1・予鈴 3.17:1・超過 4.13:1、ベルの行の「ここで黄（予鈴）に」3.68:1）と入力欄の枠（1.44:1）が WCAG AA に届かない。初期化時の確認で、トークンの値とモックどおりの適用のまま許容すると決めた（状態はリング・ラベルの文言・明滅でも伝わるため）。ダークテーマはすべて基準を満たす
- **対応環境**：主な対象は Chrome（Windows・macOS・Android）の最新版。Edge の最新版でも動くこと。iOS Safari は表示と計測が動けばよい扱いとし、動作確認は Chrome を優先する。振動と全画面は iOS では対象外
- **画面幅**：スマートフォンの幅（390px）からデスクトップ（1280px以上）まで、横スクロールなしで使える。720px以上で広い画面の配置に切り替える

## 4. 技術スタック

| 項目 | 採用バージョン | 選定理由 |
|---|---|---|
| UI フレームワーク | SvelteKit 3.0.x（Svelte 5） | 画面1枚で状態を多く持つアプリを、1つのフレームワークで完結できる。2026年10月1日に正式版が出ており、新規に始めるなら最新系を使う |
| 出力 | `@sveltejs/adapter-static` 4.x | サーバー処理が要らない。静的ファイルとしてプリレンダリングする |
| PWA | SvelteKit 標準のService Worker（`$service-worker`）、手書きの `manifest.webmanifest` | 事前キャッシュだけで足りるので、PWAプラグインを足さない。依存が少なく、保守の不安もない |
| 言語 | TypeScript | 既定どおり |
| パッケージ管理・実行 | Bun 1.4.x | 既定どおり |
| 音 | Web Audio API（ベル音は合成する） | 音源ファイルが不要で、ライセンス確認も要らない。音量の調整がしやすい |
| 端末機能 | Screen Wake Lock API、Fullscreen API、Vibration API | いずれも対応していない環境では機能を隠すか、警告を出す |
| ホスティング | Cloudflare Pages（GitHub 連携） | push だけでビルドと公開が終わり、手数が最も少ない |

参考に、執筆時点の最新版は SvelteKit 3.0.1、Bun 1.4.2 です。

注記（初期化時の確認）: SvelteKit 3 では `$service-worker` モジュールが廃止された。標準の Service Worker（`src/service-worker/`）はそのまま使い、`$app/manifest`・`$app/env`・`$app/paths` から必要な値を読み込む。PWAプラグインを足さない方針は変わらない。

## 5. アーキテクチャ概要

責務ごとに分け、互いをインターフェース越しに使う。画面は下の層に依存してよいが、下の層は画面を知らない。

| 責務 | 内容 | 依存 |
|---|---|---|
| タイマー（純粋なTS） | 開始・一時停止・再開・終了の状態遷移を扱う。現在時刻を受け取り、残り・経過・超過・状態（通常／予鈴／超過／一時停止）を返す | 時刻の取得を差し替えられるようにし、テストできるようにする |
| ベル判定（純粋なTS） | 設定と経過時間から、鳴らすべきベルと次のベルを求める。同じベルは二度鳴らさない | タイマーの結果だけを使う |
| 出力 | 音（Web Audio）、振動。「鳴らす」インターフェースの実装として持つ | ブラウザAPI |
| 端末機能 | スリープ防止、全画面。使えるかどうかと失敗の通知を返す | ブラウザAPI |
| 設定 | 持ち時間・ベル・表示名・音量・振動・テーマを1つのストアで持ち、検証する（持ち時間0、鳴らないベル） | 保存インターフェース |
| 保存 | 読み込みと書き込みのインターフェースだけを定義する。現在は「何もしない」実装を使う | 将来の名前付きプリセットのときに、端末内ストレージの実装へ差し替える |
| 画面（Svelte） | S00〜S03f の表示と入力。タイマーと設定の状態を描画するだけで、計算はしない | 上記すべて |

- 画面遷移は、1ページ内の表示切り替えで行う（設定 ⇄ 計測）
- URLのルーティングは使わない

## 6. デザインシステム

### 同梱するデザインアセット

- `lt_time_keeper_mock_v1.html`：画面構成の正本
- `lt_time_keeper_tokens_v1.css`：値の正本（色・タイポグラフィ・余白・角丸・影・モーション）
- `lt_time_keeper_icon_master_v1.svg`：アイコンの正本
- `lt_time_keeper_brand_v1.md`：方向性（形容詞・モチーフ・避けたいもの）とアイコンの余白ルール

### 画面ID一覧

| ID | 画面名 |
|---|---|
| S00 | 起動中 |
| S01 | 設定（初期状態） |
| S01a | 設定：入力エラー |
| S01b | 設定：ベルなし |
| S01c | 設定：ベル多数・長い表示名 |
| S01d | ベルの編集 |
| S01e | テーマの切り替え |
| S01f | 更新のお知らせ |
| S03 | 計測中（通常） |
| S03a | 計測中（予鈴後）・長い表示名 |
| S03b | 計測中（超過） |
| S03c | 一時停止 |
| S03d | 警告表示 |

| S90 | 部品の状態（hover・focus・disabled） |

S02（開始待ち）と S04（まとめ）は検討の結果、不採用にしたため欠番です。

### 原則

- **くっきり・落ち着き・頼れる**（`lt_time_keeper_brand_v1.md`）
- 計測画面では、残り時間の数字とリングを最優先にする。そのほかの要素は控えめにし、操作がないときは隠す
- 数字は等幅数字にする。桁が変わっても幅が揺れないようにする
- 状態色（緑・黄・赤）は状態を示すためだけに使い、操作系の色と混ぜない
- 登壇者を威圧する演出（速い点滅、大きな警告）はしない

### コンポーネント方針

- スタイルの値は、すべて `lt_time_keeper_tokens_v1.css` のCSSカスタムプロパティから参照する。値を直接書かない
- ボタン（主・通常・ゴースト・アイコン・危険）、入力欄、プリセット、状態ラベル、ベルの行、シート、ダイアログ、警告バナーを部品として作り、S90 の状態をすべて再現する
- ライト・ダークは `data-theme` 属性とOS設定の両方で切り替える。仕組みはトークンファイルの構造に従う
- 広い画面の配置は、コンテナクエリまたはメディアクエリで切り替える

### 確定事項（変更禁止）

- トークンの値（`lt_time_keeper_tokens_v1.css`）
- 画面構成：画面ID、要素と配置、遷移、描いた状態（`lt_time_keeper_mock_v1.html`）
- マスターSVG（`lt_time_keeper_icon_master_v1.svg`）
- アイコンの余白ルール（`lt_time_keeper_brand_v1.md` の「アイコン」）

### 委任事項（エージェントに任せる）

- モックの実装方式（コンポーネントの分け方、CSSの書き方）
- 各形式へのアイコン展開：favicon、PWA用PNG（192・512px、maskable）、Apple touch icon、OGP画像。マスターSVGから Bun のスクリプトで生成し、生成物はリポジトリに含める
- トークンの適用
- 縮小表示の確認
- ベル音の音色の作り方（Web Audio での合成方法）
- 計測画面の再描画の間隔

モックの枠（ブラウザの枠、端末の枠）、`--mock-` で始まる値、vw を cqi に読み替えている部分は、モック表示のためだけのものです。実装では `vw`・`vh` のまま使います。モック内のリングは `stroke-dasharray` で描いていますが、描き方は委任事項です。

## 7. 配布・公開方法

- **ホスティング**：Cloudflare Pages に GitHub リポジトリを連携する
- **ビルド設定**：
  - ビルドコマンド：`bun run build`
  - 出力ディレクトリ：`build`
  - 環境変数：`BUN_VERSION` に採用した Bun のバージョンを指定する（Pages のビルド環境の既定は 1.2.15 のため）
- **公開先**：独自ドメイン `lt.rinontech.com`
- **反映**：`main` へのpushで本番に反映される。ほかのブランチはプレビューになる
- **CI**：GitHub Actions は `v*` タグのpushで起動し、型チェック・テスト・ビルドを行って、GitHub Releases にドラフトを作る。公開は上記の Pages 連携が行い、Actions からはデプロイしない
- **バージョン**：SemVer を使う。`package.json` の `version` と Git タグ `vX.Y.Z` をそろえる。commit・push・tag はユーザーが行う
- **PWAの更新**：Service Worker のキャッシュ名にバージョンを含め、新しいバージョンで古いキャッシュを消す。新しい Service Worker が待機状態になったら S01f で知らせ、「再読み込み」で切り替える

## 8. スコープ外

- 設定の保存、名前付きプリセット（将来の拡張候補。保存インターフェースだけ用意する）
- 複数の登壇者・枠を並べたプログラム進行
- 複数端末の連携（スマホで操作、PCで表示など）
- 計測結果の記録・履歴・書き出し
- 音源ファイルの読み込み、ベル音の選択
- 多言語対応（日本語のみ）
- アカウント、サーバー、解析ツール

## 9. 未決定項目

なし。初期化時の確認（261011205635）で、次の点を決めて本文に反映した。

- 予鈴・超過・一時停止のときは、経過時間の代わりに状態ラベルを出す（モックどおり）
- ベルの番号の表記と、補足文の決まり方（メモ欄は設けない）
- 鳴らないベルの境界、同じ時点のベル、入力の上限、追加時のシート、音量・振動の初期値
- 全画面ボタンは広い画面でだけ出す（モックどおり）
- ライトテーマのコントラスト未達を許容すること
- CIはタグで起動し、公開は Pages 連携が行う
- OGP画像もアイコン展開に含める
